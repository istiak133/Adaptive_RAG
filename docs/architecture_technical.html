Adaptive Document Preparation System — Engineering Blueprint

RAG MCQ generator with a closed adaptive loop. Two storage engines, dual retrieval, and persisted cross-session mastery memory — orchestrated as a LangGraph state machine.

PostgreSQL — relational source of truth ChromaDB — vector index adaptive feedback loop

② DUAL STORAGE · why two engines

PostgreSQL

11 tables · 4 layers · structured truth, history & adaptive state

STRUCTURE
sections · chunks (content, pages, cross_refs, kind)
TOPIC GRAPH
topics · section_topics (depth) · chunk_topics · question_topics (is_primary)
SESSIONS
sessions (score, is_cold_start, adaptive_context) · questions · answers
MASTERY (memory)
topic_mastery (global: weight, streak, is_mastered) · section_topic_mastery (per-section)

ChromaDB

vector index — semantic ranking only

• 195 chunk embeddings, 384-dim (MiniLM)
• HNSW index, cosine similarity
• minimal metadata for filtering:
section_id · chunk_kind · pages · cross_refs
No business logic here — it answers “which text is relevant”, nothing about the user.
🔑 sub_section_id — the same key lives in BOTH stores → join vector hits back to full relational rows
FK policy: CASCADE almost everywhere, but RESTRICT on questions.section_id — a section can’t be deleted while historical questions reference it (protect the audit trail).
③ DUAL RETRIEVAL · two different questions, fused

CONTENT retrieval — “what is there to ask about?”

reads ChromaDB → then PostgreSQL

  • embed the query seed → ChromaDB HNSW search
  • filter: section_id ∈ chosen, exclude glossary noise
  • top-k sub_section_ids (ranked by similarity)
  • fetch full ORM rows from Postgres, re-order to preserve Chroma’s ranking
  • cross-reference resolution: pull §X.Y referenced chunks (depth 1; merged-id LIKE match)
  • token-budget filter → fits the context window

HISTORY retrieval — “what is THIS user weak at?”

reads PostgreSQL mastery tables

  • read topic_mastery + section_topic_mastery + section_topics.depth
  • Allocator: effective weight = global × section × depth
    (depth 1.0 / 0.6 / 0.3) → sort desc
  • proportional split into per-topic query seeds (weakest get more; every weak topic guaranteed ≥1)
  • modes: cold · adaptive · all_mastered · all_weak
  • Adaptive-context: WEAK / MASTERED summary + “avoid these recent questions”, token-budgeted (3-level compression)
▼   both lanes fuse in   ▼
Prompt assembly (LangChain)   content chunks (from lane 1)  +  topic seeds & WEAK/MASTERED summary (from lane 2)  +  JSON schema / format instructions
Why dual? A vector DB can’t tell you which topic a user keeps failing; relational tables can’t do fuzzy semantic ranking. Lane 1 finds relevant material; lane 2 makes it personal. Mastery weights decide which seeds drive the semantic search.

⑤ SCORE + CLOSE THE LOOP

Record

persist questions + question_topics (primary/secondary links)

Simulate + score

answer each Q (strategy), compute per-session score

Update mastery (cascade)

for every linked topic: streak math, weight = 1 + wrong×0.5×impact, clamp [0.1, 5.0]

Regression guard

was mastered & now wrong → un-master + bump weight to floor 2.5

impact = 1.0 primary / 0.5 secondary · correct → streak=max(0,s)+1 · wrong → streak=min(0,s)−1 · writes back to the two mastery tables.
↺ ADAPTIVE LOOP — every answer rewrites mastery weights in Postgres → the next session’s HISTORY retrieval (③ lane 2) reads new weights → different seeds → different questions. Memory is persisted relational state, not in-RAM.
Orchestration — LangGraph state machine. detect_mode → (adaptive? load_context) → create_session → generate → validate → record → simulate&score → complete, with 2 real conditional edges: cold ↔ adaptive and validate → retry. Two memory scopes: PrepState (TypedDict) = in-run working memory · PostgreSQL = cross-session long-term memory.
Hard: dual-store consistency via bridge key + rank-preserving re-order Hard: cross-ref graph walk (merged-id matching) Hard: proportional allocation with per-topic guarantees Hard: regression detection on mastered topics Hard: token-budgeted history with 3-level graceful compression Hard: hallucination guard grounded in source text
